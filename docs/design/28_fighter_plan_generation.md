# FCM Delegated Design 28 — 선수 계획 생성과 Combat Intelligence

> 상태: 수치는 초기 후보이며 밸런싱 전이다.
> 기준: [콤보형 턴제 전투](18_combo_turn_combat_and_information_cards.md), [Action Result 판정](26_action_result_resolution.md)
> 실물 Config: `config/combat_ai.json`
> 범위: NPC와 위임된 선수가 8칸 계획을 만드는 방식. 플레이어 직접 조작은 대상이 아니다.

## 해결하는 문제

"상대 계획 확정 → 정보 공개 → 플레이어 확정"이라는 순서는 확정됐지만
NPC가 *어떻게* 계획을 세우는지에 대한 명세가 없었다. 시제품은 고정 패턴 배열을 쓴다.

Fight IQ와 Tactical Execution은 18개 Base 중 둘인데, 이 둘이 실제로 무엇을 바꾸는지도 정의되지 않았다.
이 문서가 그 둘의 유일한 주 작동 지점이다.

---

# 1. 계획 생성 파이프라인

```text
read_context      현재 상태, 포지션, 거리, 라운드, 코치 지시
predict_opponent  Combat Memory에서 상대 행동 예측 분포 생성
generate_candidates 후보 8칸 계획 다수 생성
evaluate          기대 이득 - 기대 위험 - 비용, 성향 가중
select            최고 평가 선택
execution_noise   Tactical Execution에 따른 흔들림
commit            잠금. 이후 변경 없음
```

## 난수의 위치

**모든 난수는 `commit` 이전에만 존재한다.**

계획 생성은 흔들릴 수 있지만, 일단 잠긴 뒤의 판정은 26번에 따라 완전히 결정론적이다.
따라서 "Randomness creates variation, not causation" 원칙과 충돌하지 않는다.
난수가 **누가 이기는지**를 뽑지 않고 **무엇을 시도하는지**만 흔든다.

---

# 2. Fight IQ — 예측의 품질

Fight IQ는 숨겨진 정보를 사지 않는다. **예측의 정확도와 탐색의 폭**을 산다.

| 축 | 낮을 때 | 높을 때 |
|---|---|---|
| 후보 탐색 수 | 3개 | 24개 |
| 예측 신뢰도 | 0.15 | 0.80 |
| 기억 창 | 직전 1턴 | 최근 6턴 |
| 최근성 과적합 | 큼 | 작음 |

**최근성 과적합이 핵심이다.** Fight IQ가 낮은 선수는 직전 한 턴에 과도하게 반응한다.
플레이어가 한 번 훅을 쓰면 다음 턴에 위빙만 잔뜩 깔아두는 식이다. 그리고 그것이 읽힌다.

Fight IQ가 높은 선수는 여러 턴에 걸친 경향을 본다. 한 번의 미끼에 넘어가지 않는다.

예측은 분포이지 정답이 아니다. 신뢰도 최대값이 0.80인 이유는 **완전한 예측을 허용하지 않기 위해서**다.

---

# 3. Tactical Execution — 계획의 충실도

선택한 계획을 그대로 실행하지 못한다.

- 배치가 한 칸씩 밀림
- 의도한 카드가 비슷한 다른 카드로 바뀜
- 순서가 뒤바뀜
- 코치 지시를 덜 반영함

같은 전략을 줘도 Tactical Execution이 낮으면 다른 경기가 나온다.
**좋은 지시가 곧 좋은 실행이 아니다.** 23번의 코너 지시가 실제 의미를 갖는 지점이다.

`instruction_adoption`은 플레이어가 준 지시를 얼마나 따르는지를 직접 결정한다.
낮은 선수는 코치가 아무리 정확해도 자기 습관대로 싸운다.

---

# 4. NPC 정보 카드 — 순환 문제의 해결

`18번`이 "별도 설계한다"며 미뤄둔 항목이다.

## 문제

NPC가 정보 카드로 상대 계획을 읽으려면 상대 계획이 이미 있어야 한다.
그런데 순서상 **NPC가 먼저 확정하고 플레이어가 나중에 확정한다.**
플레이어 확정 후 NPC가 재계획하면 확정 구조 자체가 무너지고 치팅으로 느껴진다.

## 해결: 회고적으로만 작동한다

**NPC의 정보 카드는 현재 턴을 읽지 않는다. 과거 턴에 대한 관찰을 정밀하게 만든다.**

- 예측 신뢰도 상승
- 기억 창 확대

Config에 `read_current_turn_plan`과 `replan_after_reveal`을 금지 목록으로 둔다.

결과적으로 정보 카드를 가진 NPC는 "내 습관을 더 잘 읽는 상대"로 체감된다.
플레이어 쪽 정보 카드와 효과가 비대칭이지만, 그 비대칭은 확정 순서에서 나오는 구조적 결과이며 설명 가능하다.
대칭을 억지로 맞추려면 확정 순서를 깨야 하고, 그것이 훨씬 큰 손실이다.

# 5. 성향과 전략

시제품의 압박형·교란형·수비형을 평가 함수의 **가중치 세트**로 일반화한다.
별도 Personality 시스템이 아니다. SSOT가 금지한 고정 성격 데이터를 만들지 않는다.

성향은 선수의 스타일과 코치 지시에서 나오며, 지시가 가중치를 일시적으로 덮어쓴다.

## 반복 패널티

평가 함수에 `pattern_repetition_penalty`를 둔다.

이것이 없으면 평가가 정확해질수록 하나의 최적 루프로 수렴하고, 그 순간 완전히 읽히는 상대가 된다.
**잘 싸우는 AI가 지루한 AI가 되는 것을 막는 항목이다.**

## 생존 오버라이드

스태미너가 바닥나거나 그로기 상태면 성향과 무관하게 회복·방어로 기운다.
이는 별도 성격이 아니라 **상태에 대한 반응**이다. 모든 선수에게 동일하게 적용된다.

---

# 6. 확정 구조 불변식

- NPC는 플레이어가 편집 중인 계획을 읽지 않는다
- NPC 계획은 정보 공개 **이전에** 잠긴다
- 공개 이후 재생성하지 않는다
- 같은 Seed와 같은 턴 시작 상태는 같은 계획을 만든다

시제품은 정적 클라이언트 앱이라 개발자 도구 수준의 치팅은 막지 못한다.
이는 싱글플레이 범위의 한계이며 `19번`에 이미 기록돼 있다.

---

# 7. 미결 항목

- 후보 계획 생성 방식. 템플릿 조합인지 탐색인지
- 평가 함수의 기대값 계산 깊이. 한 턴인지 다음 턴까지인지
- 예측 분포를 Combat Memory에서 만드는 구체 식
- 위임된 아군 선수와 NPC가 같은 파이프라인을 쓰는지
- Skill Card가 평가 가중치에 개입하는 방식
- 성향 프리셋이 Fighter 데이터의 어디에 저장되는지
- 난이도 조절을 Fight IQ로 할지 별도 축으로 둘지

---

# 8. 검증 기준

- 같은 Seed와 같은 턴 시작 상태에서 같은 계획이 나온다
- 플레이어가 계획을 바꿔도 NPC 계획이 바뀌지 않는다
- 정보 공개 전후로 NPC 계획이 동일하다
- Fight IQ만 다른 두 선수가 관찰 가능하게 다른 행동을 한다
- Fight IQ가 낮은 선수가 직전 턴에 과반응한다
- Tactical Execution만 다른 두 선수가 같은 지시에서 다른 결과를 낸다
- 반복 패널티를 끄면 행동이 단조로워지는 것이 확인된다
- NPC가 현재 턴의 플레이어 계획을 참조하는 경로가 코드에 존재하지 않는다
- 예측 신뢰도가 1.0에 도달하지 않는다
