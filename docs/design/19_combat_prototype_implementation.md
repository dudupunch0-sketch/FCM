# 콤보 링 — 첫 전투 시제품 구현

## 플랫폼 결정

현재 단계에는 브라우저의 Canvas + JavaScript 모듈을 선택한다. 최종 상용 게임 엔진의 영구 확정은 아니다.

| 선택지 | 이번 과제에서의 판단 |
|---|---|
| 브라우저 + Canvas | 설치 없이 배포·피드백 가능. 카드 중심 UI와 절차적 관절 애니메이션을 한 프로젝트에서 구현할 수 있어 채택 |
| Godot 네이티브 | 씬 편집, 애니메이션 제작 및 데스크톱 확장 시 재평가할 후보. 현재 기존 아트 파이프라인이 없어 전투 검증을 우선 |
| Godot 웹 내보내기 | 브라우저 배포도 가능하지만 웹 전용 제한을 함께 검토해야 함. 이번 전투에는 별도 엔진 런타임이 필수는 아님 |

근거 문서:
- [MDN Canvas 애니메이션](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Basic_animations)
- [Godot 웹 내보내기 및 제한](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html)

요청 범위에 대한 개발 판단이며 네이티브 엔진과의 실측 성능 비교는 아니다.
전투 엔진을 화면에서 분리한다. 향후 이벤트 계약과 테스트 사례를 재사용할 수 있지만 다른 언어로 옮길 때 코드 이식은 필요할 수 있다.

## 구현 범위와 구조

| 파일 | 역할 |
|---|---|
| `dist/engine.js` | DOM과 무관한 계획·부분 관찰·판정. 애니메이션 시계를 읽지 않음 |
| `dist/ring.js` | Canvas 관절 애니메이션, 공격·가드·회피·피격·다운, 타격 효과 |
| `dist/app.js` | 상대/정보카드 선택, 콤보 편집·순서 변경, 예시 콤보, 입력, 재생/스킵/속도/효과음 |
| `tests/combat.test.mjs` | 결정성, 정보 공개, 방어/카운터, 경계 조건과 경기 종료 검증 |

머리/몸통/팔 손상, 스태미너 비용·회복, 페이크와 실제 회피 후 카운터를 구현했다.
상대 계획을 먼저 확정한 후 관찰 정보만 UI에 전달한다. 다만 정적 클라이언트 앱이므로 개발자 도구를 통한 치팅 방어는 제공하지 않는다. 싱글플레이 시제품 범위다.

## 시제품 임시 규칙

아래는 재미 검증용이며 최종 밸런스 확정이 아니다. `RULES`와 `CARDS`에서 조정한다.

- 한 교환은 8칸, 동작은 1~4칸. 빈칸은 호흡 정리다. 동일 동작의 반복 사용을 허용한다.
- 잽은 시작 박자, 다른 공격은 시작 다음 박자에 타격한다. 회수 시간은 카드 점유 안에 포함한다.
- 같은 박자 공격은 같은 스냅샷으로 판정 후 함께 반영한다. 일반 피격은 남은 계획을 취소하지 않는다. KO는 교환을 종료한다.
- 동작 시작 때 비용을 지불한다. 부족하면 해당 동작은 실패하고 후속 동작은 예정 시점에 재시도한다.
- 가드 접촉 비용을 낼 수 없으면 가드가 무너진다. 블록에도 관통 충격과 팔 손상이 있다.
- 스웨이는 직선, 위빙은 훅 궤도만 피한다. 몸통 공격은 두 회피 모두 공략한다.
- 실제 회피 후 카운터는 이어지는 2박까지 유효하며 공격에 사용하거나 교환이 끝나면 소멸한다.
- 페이크는 상대가 유효 가드/회피 중일 때만 빈틈을 만든다. 후속 공격에 소모되고 영구 이월되지 않는다.
- 정보 카드 하나를 경기 전 선택해 고정한다. 전체 게임의 활성 카드 한도를 대체하지 않는다.
- 패턴 독해는 직전 콤보와 같은 위치/동작을 최대 두 개 공개한다. 강타 감지는 강타 또는 페이크에서 최대 두 예고를 만든다.
- 경기 라운드 시계는 미연결이다. 최대 12교환 후 유효 타격과 방어 점수로 간단 판정한다.
- 머리 충격 KO 경계와 순간 타격 조건은 `RULES`에 둔다. 전신 HP를 도입하지 않는다.

## 한계와 다음 연결 지점

- 동일 기본 선수 조건을 사용한다. 기존 Base → Derived → Effective 전체 계산, 훈련/성장, 거리, 리치, 규칙별 판정은 미연결이다.
- MMA, 킥, 그래플링, 정교한 부상 및 다운 후 회복은 후속 범위다.
- 상대는 성향별 패턴 중 선택하며 저스태미너에서는 회복 계획을 사용한다. 플레이어 패턴을 학습하는 AI는 미구현이다.
- 애니메이션은 절차적 관절 모델이며 상용 아트, 모션 캡처, 물리 기반 접촉은 아니다.
- 접근성 레이블, 키보드 조작, 반응형 레이아웃을 포함하나 실제 브라우저/모바일 시각 QA는 별도다.
- 첫 플레이 피드백으로 순서의 의미, 정보카드 의존도, 가드 반복, 회복 템포와 타격감을 조정한다.

## 검증

`node --test tests/combat.test.mjs`로 엔진을 검증한다. 각 JavaScript 파일은 `node --check`로 구문 검증한다.
정적 엔트리포인트와 로컬 자산 참조를 확인한다. 실기기 렌더링을 확인했다는 주장은 하지 않는다.
