# FCM Delegated Design 35 — 콘텐츠 물량 목표

> 상태: 선행 조건(엔진 검증) 충족으로 유예에서 해제. 목표치는 측정으로 갱신한다.
> 기준: [구현 로드맵](../spec/implementation_roadmap_part1_part2.md) 19장, [자가 대전 균형](34_ai_equilibrium.md)
> 운영: [검증·보정 환경 지침](../guide/testing_and_calibration.md)

## 왜 지금인가

로드맵 19장은 "많은 콘텐츠로 엔진 문제를 가리지 않는다"고 못박고 물량을 엔진 검증 뒤로 미뤘다.
엔진은 이제 243개 테스트, 밸런스 도구, 균형 보정 환경을 갖췄다. 선행 조건이 충족됐다.

---

# 1. 물량을 세지 않고 흡수량으로 정한다

"Action Card 40종"처럼 개수를 목표로 잡지 않는다.
개수는 달성하기 쉽고 **아무것도 보장하지 않는다.** 죽은 카드 30종을 더해도 목표는 달성된다.

대신 **균형이 실제로 흡수하는 양**을 기준으로 삼는다.

> 콘텐츠 목표는 "몇 개를 만들었나"가 아니라 **"만든 것 중 몇 개가 최적 플레이에 등장하나"**다.

`npm run calibrate:report`가 균형에서 쓰이지 않는 카드를 직접 알려준다.

---

# 2. 현재 상태

| 축 | 현재 | 균형 등장 |
|---|---|---|
| Action Card | 14종 | 11종 |
| 정보 스킬카드 | 5종 | 미측정 |
| 상대 프로필 | 3종 | — |
| 스타일 스킬카드 | 0종 | — |

**균형 미등장 3종: `hook`, `lowguard`, `flicker`.**
이것이 현재의 실질적 콘텐츠 문제다. 새 카드를 만들기 전에 이 셋을 살리거나 빼야 한다.

스타일 스킬카드는 아직 0종이다. 31번이 한도를 5장으로 정해뒀지만 내용물이 없다.

---

# 3. 단계별 목표

물량은 검증 단계에 종속된다. 각 단계는 **앞 단계의 건강 지표를 통과해야** 시작한다.

## 단계 A — 현재 콘텐츠 정리 (선행)

새로 만들지 않는다. 지금 있는 것을 건강하게 만든다.

- 균형 미등장 카드 **0종**
- 스타일 스킬카드 **3종** 도입 후 31번의 "스타일이 실제로 쓰이는가" 확인

이 단계를 건너뛰고 물량을 늘리면 죽은 콘텐츠 위에 죽은 콘텐츠를 쌓게 된다.

## 단계 B — 복싱 완성

- Action Card **20~24종**, 균형 등장률 **70% 이상**
- 정보 스킬카드 5종 유지, 각 카드가 균형에서 선택되는 상황이 존재
- 스타일 스킬카드 **8~12종**, 활성 5장 조합이 실제로 갈림
- 상대 프로필 **5~6종**, 각 프로필의 균형이 서로 달라야 함

## 단계 C — Ruleset 확장

킥복싱·MMA는 [27번](27_position_and_grappling.md)의 포지션 시스템 구현 이후다.

- Ruleset당 고유 Action **10종 이상**
- 포지션별(Standing/Clinch/Ground) 최소 행동 집합 확보
- Ruleset별 균형을 따로 푼다

---

# 4. 건강 지표

물량과 무관하게 항상 유지해야 하는 값이다.

| 지표 | 기준 | 확인 |
|---|---|---|
| 균형 등장률 | 70% 이상 | `calibrate:report` |
| 지배 전략 | 0개 | `balance combat` |
| 균형 지지집합 | 카드 수에 따라 함께 증가 | `calibrate` |
| 외부 최적대응 이득 | 0.3 이하 | `calibrate` |

**지지집합이 자라지 않는데 카드만 늘면 새 카드가 전부 열등하다는 뜻이다.**

---

# 5. 새 카드를 추가하는 절차

1. 기존 카드와 **다른 축**에서 선택을 만드는지 먼저 말로 설명한다. 설명이 안 되면 만들지 않는다
2. `config/combat_prototype.json`에 추가한다. 코드 변경이 필요하면 축이 아직 없다는 뜻이다
3. `npm run calibrate` 재실행
4. `calibrate:report`에서 균형에 등장하는지 확인
5. 등장하지 않으면 수치를 고치거나 **뺀다.** 남겨두지 않는다

`flicker`와 `advance`가 좋은 예다. 둘 다 코드 변경 없이 Action Data만으로 추가됐다.
`advance`는 균형에 등장하고 `flicker`는 등장하지 않는다. 후자는 현재 실패 사례다.

---

# 6. 미결 항목

- 정보 스킬카드의 균형 등장 측정. 현재 균형 계산은 정보 공개를 모델에 넣지 않는다
- 스타일 스킬카드를 균형 계산에 넣는 방법. 계획이 아니라 조건부 효과라 축이 다르다
- 단계 B의 20~24종이 적정한지. 8칸 타임라인이 흡수할 수 있는 상한은 미측정이다
- Technique과 Action Card의 대응 관계. 현재 시제품은 Technique 계층이 없다

---

# 7. 검증 기준

- `calibrate:report`의 미등장 카드가 목표 등장률을 만족한다
- 카드를 늘렸을 때 균형 지지집합도 함께 커진다
- 새 카드 추가에 엔진 코드 변경이 필요하지 않다
- 지배 전략이 0개로 유지된다
- 단계 A를 통과하기 전에 단계 B 물량을 만들지 않는다
