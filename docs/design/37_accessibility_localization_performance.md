# FCM Delegated Design 37 — 접근성·현지화·성능

> 상태: 접근성과 현지화는 유예 해제. **성능 목표는 실기기 QA 전이므로 일부만 확정한다.**
> 기준: [화면별 정보구조](36_screen_information_architecture.md)

세 항목을 한 문서에 두는 이유는 모두 **화면과 문자열이 생긴 뒤에야 정할 수 있는 것들**이고
서로 경계가 맞닿아 있기 때문이다.

---

# 1. 접근성

## 난이도와 접근성은 다른 축이다

33번이 이미 구분했다. 난이도는 **도전의 크기**, 접근성은 **조작과 인지의 부담**이다.
접근성 옵션이 게임을 쉽게 만들어서는 안 되고, 난이도 옵션이 조작 부담을 줄여서도 안 된다.

## 확정 사항

| 축 | 규칙 |
|---|---|
| 색 | **색만으로 정보를 전달하지 않는다.** 확정/추정은 실선·점선으로 이미 구분한다. 상태는 색 + 문자 |
| 모션 | 감소 모드에서 화면 흔들림·타격 정지·입자 제거. **판정에는 영향 없음** |
| 시간 | 계획에 제한 시간을 두지 않는다. 이미 그렇다 |
| 글자 | 확대 시 문서 스크롤로 대응한다. 레이아웃이 깨지는 대신 스크롤을 허용한다 |
| 입력 | 모든 조작에 키보드 경로. 드래그 전용 조작을 만들지 않는다 |
| 레이블 | 아이콘에 텍스트 레이블 병기 |

모션 감소는 **이미 구현되어 있다**(`reduced motion suppresses bob and hit stop`).
그 테스트가 판정 불변까지 확인한다.

## 8칸 타임라인의 인지 부담

이 게임 고유의 접근성 문제다. 31번이 남긴 **선택 부하**와 같은 뿌리다.

완화 수단은 난이도가 아니라 표현이다 — 카드 그룹핑, 최근 사용 우선, 프리셋 콤보, 상황별 추천.
**추천은 기본 꺼짐**으로 둔다. 켜면 편해지되 정보량이 늘지는 않는다.

# 2. 현지화

## 현재 상태

외부화 완료. `app.js`에 번역 대상 문구가 남아 있지 않으며 테이블 항목은 85개다.

| 위치 | 상태 |
|---|---|
| 사용자 노출 문구 | `config/strings/ko.json` (85개) |
| 카드·스킬 이름과 설명 | `config/combat_prototype.json` |
| 검증·예외 메시지 | 소스에 유지 (의도적) |

세 가지 회귀 테스트가 이 상태를 고정한다 — `app.js`에 두 글자 이상 한글이 남지 않을 것,
부르는 키가 모두 테이블에 있을 것, 테이블에 아무도 안 쓰는 항목이 없을 것.
마지막 항목이 실제로 미사용 키 하나를 잡아냈다.

## 확정 사항

**사용자 노출 문자열과 개발자 문자열을 분리한다.**

| 종류 | 예 | 처리 |
|---|---|---|
| 사용자 노출 | 카드 이름, 설명, 화면 레이블 | 외부화 대상 |
| 개발자 노출 | 검증 오류, 예외 메시지 | 외부화하지 않는다 |

검증 오류는 번역하지 않는다. `definitions.js`의 108개 한국어 문자열은 전부 개발자용이며
**설계 문서의 검증 기준과 1:1로 대응**하므로 원문을 유지하는 편이 추적에 유리하다.

## 표현은 판정 계층에서 분리한다

외부화를 시작하자 더 근본적인 문제가 드러났다. **엔진이 이벤트마다 사용자 문구를 직접 만들고 있었다.**
번역 이전에 판정 계층이 표현을 들고 있었던 셈이다.

엔진은 이제 데이터만 낸다(`type`, `actor`, `card`, `power`, `outcome` 근거).
문구는 `dist/commentary.js`가 문자열 테이블로 조립한다.
테스트가 엔진 소스에 `text:`가 없음을 강제한다.

## 콘텐츠 문자열은 이미 Config에 있다

카드 이름과 설명은 `config/combat_prototype.json`에 있다.
현지화는 **Config에 언어 레이어를 더하는 것**이지 코드를 고치는 일이 아니어야 한다.

```
config/
  combat_prototype.json      # 구조와 수치
  strings/ko.json            # 사용자 노출 문자열 (기준 언어)
```

구현됨. `dist/strings.js`가 테이블을 읽고 `t(key, params)`로 치환한다.

## 한국어를 기준 언어로 둔다

번역 누락 시 한국어로 대체(fallback)한다. 빈 문자열이나 키를 노출하지 않는다.

# 3. 성능

## 정직하게 나눈다

**측정할 수 있는 것과 없는 것을 구분한다.** 실기기 QA를 수행하지 않았으므로
렌더링·발열·배터리에 대한 목표는 세우지 않는다. 세우면 근거 없는 숫자가 된다.

## 헤드리스로 측정한 현재 값

| 항목 | 측정값 |
|---|---|
| Config 로드 + 전체 검증 | 31ms |
| 교환 1회 판정 | 0.46ms |
| 균형 재보정 1회 | 약 157초 |
| JS 합계 | 182KB |
| 스프라이트 아틀라스 | 3.8MB |
| `dist` 전체 | 4.1MB |

## 확정하는 예산

측정 가능한 축에 대해서만 예산을 둔다.

| 항목 | 예산 | 근거 |
|---|---|---|
| Config 로드 + 검증 | 100ms 이하 | 현재 31ms. 검증을 늘려도 여유 |
| 교환 1회 판정 | 2ms 이하 | 현재 0.46ms. 12교환 경기가 판정만으로 24ms |
| JS 합계 | 400KB 이하 | 현재 182KB |
| 균형 재보정 | 10분 이하 | 개발 반복 주기를 해치지 않는 선 |

**아틀라스 3.8MB가 배포 용량의 대부분이다.** 현재 알려진 최대 항목이며 압축 여지가 있다.

## 실기기 QA가 필요한 미확정 항목

아래는 **측정 없이 목표를 세우지 않는다.**

- 목표 프레임률과 타깃 기기 등급
- 모바일 GPU에서의 스프라이트 렌더 비용
- 초기 로딩 시간(네트워크 포함)
- 발열·배터리
- 저사양 기기에서의 아틀라스 메모리

QA 수행 후 이 절을 채운다.

# 4. 미결 항목

- 두 번째 언어 테이블 추가 시의 실제 누락 검출 절차
- 접근성 옵션의 저장 위치. 세이브인지 기기 설정인지
- 아틀라스 압축 방식과 목표 용량
- 키보드 조작의 구체 매핑
- 추천 기능이 난이도로 새지 않는지 검증하는 방법

---

# 5. 검증 기준

- 색만으로 구분되는 정보가 없다
- 모션 감소가 판정 결과를 바꾸지 않는다
- 모든 조작에 키보드 경로가 있다
- 사용자 노출 문자열이 Config에 있고 코드에 없다
- 검증 오류 메시지는 외부화 대상이 아니다
- 번역 누락 시 키가 아니라 기준 언어가 나온다
- 측정 가능한 성능 예산을 초과하지 않는다
- 측정하지 않은 항목에 목표 수치를 적지 않는다
