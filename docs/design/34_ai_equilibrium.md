# FCM Delegated Design 34 — 자가 대전 균형과 AI 난이도 보정

> 상태: 보정 환경 구현 완료. 수치는 재실행으로 갱신한다.
> 기준: [선수 계획 생성](28_fighter_plan_generation.md), [난이도](33_difficulty.md)
> 도구: `tools/calibrate.mjs` · 구현: `dist/equilibrium.js`, `dist/plan-space.js`
> 산출물: `config/ai_strategies.json`

## 목적

이 문서는 특정 수치를 확정하기 위한 것이 아니라 **다시 계산할 수 있는 환경**을 정의한다.
카드·공식·밸런스가 바뀌면 이전에 구한 AI 전략은 **다른 게임의 정답**이 된다.
그때 사람이 감으로 다시 맞추는 대신 도구를 다시 돌린다.

---

# 1. 왜 딥러닝이 아닌가

전투는 결정론적이다. 같은 계획 쌍은 항상 같은 결과를 낸다.
따라서 계획 A 대 계획 B의 값은 **표본이 아니라 정답**이다.

신경망은 잡음 섞인 데이터에서 함수를 근사하는 도구다. 근사할 대상이 없다.
이것은 학습 문제가 아니라 **2인 제로섬 행렬 게임**이며 정확히 푸는 방법이 이미 있다.

ML 문헌에서 가져오는 것은 알고리즘이지 신경망이 아니다.

| 가져온다 | 가져오지 않는다 |
|---|---|
| 자가 대전 데이터 생성 | 신경망 |
| 최적 대응 반복 (fictitious play) | 경사하강 |
| Double oracle로 공간 확장 | 학습 프레임워크·GPU |
| Exploitability를 지표로 | 외부 의존성 |

의존성 0개를 유지한다. Fictitious play는 수십 줄이고 LP 솔버가 필요 없다.

---

# 2. 계획 공간

8칸을 채우는 조합은 전부 열거할 수 없다. 1칸 카드만 6종이어도 6⁸에 이른다.

그래서 **작은 풀에서 시작해 균형을 깨는 계획을 찾아 넣는 방식**(double oracle)을 쓴다.
전체를 열거하지 않고도 "이 혼합전략을 이기는 계획이 더 이상 안 나온다"는 지점에 접근한다.

동일 스펙 선수끼리 붙인다. 능력치를 상수로 고정해야 **전략만 분리**해서 볼 수 있다.

---

# 3. 측정하는 두 값

## 게임 값 — 정합성 검사

대칭 제로섬 게임이므로 균형에서의 게임 값은 **반드시 0**이다.
0에서 벗어나면 페이오프 행렬이 반대칭이 아니게 된 것이고, 이는 전투에 좌우 비대칭이 생겼다는 뜻이다.
밸런스 지표이기 전에 **버그 탐지기**다.

## Exploitability — 난이도 그 자체

주어진 혼합전략에 대해 최적 대응이 얻는 이득이다.
0에 가까우면 빈틈이 없고, 크면 구멍이 있다.

**난이도는 이 값이다.** 별도의 난이도 축을 발명할 필요가 없다.

### 풀 내부 값과 외부 값을 구분한다

풀 내부 exploitability는 **이미 아는 계획만** 본다. 이 값은 수렴을 과대평가한다.

실제로 초기 구현에서 풀 내부 값이 0.012인데 풀 밖에서 찾은 최적 대응은 이득 1.0을 냈다.
둘을 함께 보고하고, **수렴 판단은 외부 값으로 한다.**

---

# 4. 이 게임은 강하게 순환적이다

측정에서 드러난 성질이다. 지지집합이 3개 계획에 33%씩 머무는 가위바위보 구조가 반복해서 나타났고,
셋 모두를 이기는 계획이 매번 존재했다.

그래서 **라운드당 최적 대응 하나만 추가하면 수렴하지 않는다.** 새 계획이 기존 혼합을 이기고,
다시 다른 계획에 지면서 지지집합 크기가 자라지 않는다.
상위 K개를 한꺼번에 넣어 풀을 빠르게 넓혀야 안정된 혼합이 형성된다.

이 순환성 자체는 설계상 **좋은 신호**다. 지배 전략이 없다는 뜻이기 때문이다.
다만 보정 도구는 그 성질을 전제로 만들어야 한다.

## 측정이 드러낸 RNG 결함

보정 환경을 붙이자마자 혼합전략이 항상 같은 계획만 내놓았다.
원인은 계획 선택용 xorshift32가 **인접 시드의 첫 출력에서 강하게 상관**된다는 것이었다.
연속된 시드가 대략 0.94와 0.47을 번갈아 내놓아 선택이 사실상 2진값이었다.

이 결함은 고정 패턴 선택에도 이미 작용하고 있었으므로 **AI는 원래 의도보다 훨씬 단조로웠다.**
출력 몇 개를 버려 스트림을 탈상관시켰다.

**중요한 함의:** 이전 밸런스 튜닝은 망가진 RNG 위에서 측정된 값이다.
수정 후 다시 재면 지배 전략이 다시 나타났다. 보정 환경이 없었으면 발견하지 못했을 문제다.

---

# 5. 난이도로의 연결

```
가혹   = 균형 그대로            이탈 0
도전   = 균형 + 소폭 이탈       이탈 0.15
표준   = 균형 + 중간 이탈       이탈 0.40
입문   = 균형 + 큰 이탈         이탈 0.75
```

이탈분은 **풀에서 가장 약한 계획들**로 채운다.
낮은 등급의 AI는 무작위로 이상해지는 것이 아니라 **나쁜 선택을 하는 상대**가 된다.
플레이어가 실제 상대를 읽어서 이기는 경험과 같은 종류다.

33번의 원칙과 충돌하지 않는다. 난이도는 여전히 전투 수학을 건드리지 않고 **AI의 선택**만 바꾼다.

---

# 6. 밸런스 진단이 따라온다

균형 혼합전략은 밸런스 오라클이기도 하다.

- **균형에 한 번도 등장하지 않는 카드**는 죽은 콘텐츠 후보다
- **가중치가 과도하게 큰 계획**은 지배 전략 후보다
- 게임 값이 0에서 벗어나면 좌우 비대칭 버그다

`tools/balance.mjs`의 "이긴 프로필 수"는 고정 상대에 대한 근사였다.
균형해는 그것을 정확한 형태로 대체한다.

---

# 7. 재실행 절차

```bash
node tools/calibrate.mjs solve     # 다시 계산하고 config/ai_strategies.json 갱신
node tools/calibrate.mjs check     # 저장된 전략이 현재 규칙과 맞는지 검사
node tools/calibrate.mjs report    # 현재 혼합전략과 죽은 카드 확인
```

`check`가 회귀 방지 장치다. 저장된 전략에는 **전투 규칙 지문**이 함께 기록된다.
카드·공식·밸런스가 바뀌면 지문이 달라지고 `check`가 실패하면서 재계산을 요구한다.
낡은 AI가 조용히 남아 있는 상황을 막는다.

**지문은 Config뿐 아니라 `dist/engine.js` 소스도 포함한다.**
처음에는 Config만 해싱했는데, RNG 수정이 계획의 가치를 바꿨음에도 지문이 그대로였다.
판정 코드도 규칙이다.

---

# 8. 한계

- 한 경기 내내 같은 계획을 반복한다고 가정한다. 실제 플레이는 매 턴 적응하므로 이는 **하한 근사**다
- 정보 카드 공개를 모델에 넣지 않았다. 공개가 있으면 플레이어 쪽 전략 공간이 더 넓어진다
- 상대 프로필 하나(`pressure`)에 대해 푼다. 프로필별 균형은 후속 범위다
- 능력치 차이를 고정했다. 격차가 있는 매치업의 균형은 다른 문제다

---

# 9. 미결 항목

- 수렴 기준의 확정. 외부 최적대응 이득이 얼마 이하이면 충분한가
- 턴 단위 적응을 포함한 정책 수준 균형으로 확장할지
- 프로필별·격차별 균형을 각각 저장할지
- 등급별 이탈값의 실측. 현재는 설계 의도 표현이다
- 균형 계획을 그대로 NPC에 쓰면 사람처럼 보이는지. 최적이지만 기계적일 수 있다
- 고정 패턴을 균형 혼합으로 교체한 뒤의 카드 밸런스 재측정. 고정 패턴 상대로 지배적이던 계획이 혼합 상대로도 지배적인지는 별개 문제다

---

# 10. 검증 기준

- 대칭 제로섬이므로 균형에서의 게임 값이 0이다
- 페이오프 행렬이 반대칭이다
- 같은 Seed로 재실행하면 같은 혼합전략이 나온다
- 이탈이 클수록 exploitability가 커진다. 등급 순서가 뒤집히지 않는다
- 저장된 혼합전략의 가중치 합이 1이다
- 저장된 계획이 존재하지 않는 카드를 참조하지 않는다
- 전투 규칙이 바뀌면 `check`가 실패한다
- 계획 공간 샘플이 항상 8칸 제한을 지킨다
