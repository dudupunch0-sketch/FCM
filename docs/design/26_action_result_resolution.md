# FCM Delegated Design 26 — Action Result 판정

> 상태: 수치는 초기 후보이며 밸런싱 전이다.
> 기준: [거리 모델](22_combat_range_model.md), [라운드 구조](23_round_structure_and_judging.md), [Effective Performance](25_effective_performance.md)
> 실물 Config: `config/action_resolution.json`
> 범위: 4계층 전투 아키텍처의 마지막 단계. 이 문서로 `Base → Derived → Effective → Action Result`가 닫힌다.

## 해결하는 문제

`18번`이 남긴 미결 항목 대부분이 이 계층의 것이다.
동시 판정, 피격 경직, 스태미너 부족 처리, 속도 스탯의 타격 시점 반영, 회피 궤도 상성.
시제품이 임시 규칙으로 덮었지만 명세로 승격되지 않았고, 거리와 라운드가 추가되면서 다시 정의해야 한다.

---

# 1. 해상도와 스냅샷

판정 단위는 **칸(slot)** 이다.

각 칸은 칸 시작 시점의 스냅샷으로 판정한다.
**서브비트 차이가 허용 오차 이내인 타격은 같은 스냅샷으로 판정한 뒤 결과를 함께 반영한다.**
따라서 동시 KO가 성립한다.

확실히 빠른 쪽은 선타가 되지만 후속 타격을 지우지 않고 약화시킬 뿐이다. 취소는 Knockdown 이상에서만 일어난다.
서브비트와 속도의 관계는 [콤보 경계 이월과 서브비트 타이밍](30_combo_boundary_and_sub_beat.md)에 있다.

이는 25번의 "캐시는 한 칸 안에서만 유효하다"와 같은 규칙이며 재현성의 전제다.

---

# 2. 칸 판정 순서

```text
1. pay_cost          스태미너 지불. 부족하면 해당 동작 실패
2. apply_movement    range_shift 적용. shift_timing에 따라 타격 전/후로 갈림
3. impact_check      타격 시점 도달 여부. 거리 감쇠 산출
4. defense_check     회피 → 가드 → 무방비 순으로 평가
5. context_modifiers 페이크 빈틈, 카운터 창, 회수 취약, Read Confidence
6. apply_result      손상·스태미너 반영. 양측 동시
7. status_transition 상태 전이 판정
```

## 스태미너 부족

동작 시작 시점에 비용을 지불한다. 지불하지 못하면 **그 동작만 실패**하고 후속 동작은 예정 시점에 재시도한다.
계획 전체가 무너지지 않는다. 자원은 음수가 되지 않는다.

가드는 접촉 시점에 비용을 낸다. 내지 못하면 가드가 무너진다.

---

# 3. Randomness 적용 지점

명세의 핵심 철학이 실제로 구현되는 유일한 지점이므로 명시한다.

> Randomness creates variation, not causation.

**난수는 최종 Impact 크기에만, 좁은 대칭 편차(초기 ±7%)로 들어간다.**

Config에 금지 목록을 둔다.

| 금지 | 대신 |
|---|---|
| 명중/빗나감 Roll | 거리 계산과 방어 구간 겹침으로 결정 |
| 블록 성공 Roll | 가드 활성 구간과 보호 부위로 결정 |
| 회피 성공 Roll | 궤도 상성과 타이밍 겹침으로 결정 |
| Finish Roll | Impact와 Effective Durability 비교로 결정 |
| 승자 Roll | 존재하지 않음 |

같은 계획과 같은 Seed는 같은 결과를 낸다.
Upset은 상성·거리·Setup·스태미너·누적 손상에서 나오지 난수에서 나오지 않는다.

---

# 4. 방어 우선순위

**회피 → 가드 → 무방비** 순으로 평가하고, 먼저 성립한 방어가 교환을 종결한다.

## 회피

궤도 상성이 일치하고 타이밍이 겹쳐야 성립한다.
스웨이는 직선, 위빙은 훅 궤도를 피한다. 몸통 공격은 두 회피를 모두 공략한다.

- 성공: 상대 회수 구간을 노리는 **짧은 카운터 기회**(2칸). 영구 버프가 아니다
- 실패: 취약 자세에서 피격. 증폭 계수 적용

## 가드

활성 구간이 겹치고 보호 부위가 일치해야 막는다.
막아도 관통 충격과 팔 누적 손상이 있다.

**블록 비용은 흡수한 공격 비용보다 작다.** 가드가 자원 교환에서 이득을 보는 방향이며,
이는 `18번`이 확정한 방향이다. 다만 상대 스태미너를 추가로 깎는 효과는 기본으로 넣지 않는다.

## 무방비

가드도 회피도 성립하지 않으면 거리 감쇠와 상황 보정만 거쳐 그대로 들어간다.

---

# 5. Setup과 Combat Memory의 반영

패턴 노출이 축적되면 상대의 Read Confidence가 오른다.

**Read Confidence는 방어 타이밍 허용폭을 좁혀준다.** 회피와 가드가 더 정확해진다.
페이크와 패턴 파괴는 이 보정을 역으로 무너뜨린다.

양쪽 모두 Config 상한을 둔다. **읽기는 우위이지 확실성이 아니다.**
완전히 읽히면 아무것도 통하지 않는 상태가 되어 계획 자체가 무의미해진다.

---

# 6. 상태 전이

전신 HP는 없다. 전이는 **순간 Impact를 Effective Durability와 비교**해 결정한다.

```text
impact_ratio = effective_impact / (effective_durability × (1 - accumulated_weight × part_damage))
```

| 비율 | 상태 |
|---|---|
| 0.55 | Stagger |
| 0.80 | Groggy |
| 1.00 | Knockdown |
| 1.30 | KO |

누적 머리 손상이 분모를 깎으므로, 같은 펀치가 경기 초반에는 아무것도 아니고 후반에는 다운을 만든다.
**한 방의 크기가 아니라 그 시점까지의 축적이 피니시를 만든다.**

Effective Durability는 25번이 산출하며 Head Wear가 여기 포함된다.
따라서 반복 KO 이력이 실제 전투 결과로 연결된다.

Stagger와 Groggy는 회복 칸 수 동안 방어가 저하된다. 남은 계획을 취소하지는 않는다.
KO는 교환을 즉시 종료한다.

---

# 7. 원인 태그

모든 `CombatResolutionEvent`는 `cause_tags`를 채운다. 선택이 아니다.

```text
Cross 명중
+ base_impact 19.0
+ range_optimal         +0%
+ feint_opening      ×1.30
+ counter_window     ×1.35
- stamina_factor     ×0.84
- variance           ×0.98
→ effective_impact 27.4
→ impact_ratio 0.62 → Stagger
```

로드맵 §22가 요구하는 이유 추적 로그이며, 밸런스·버그·경기 후 Causal Report의 공통 기반이다.
플레이어 UI에 모두 보일 필요는 없지만 Debug Mode에서는 전부 보여야 한다.

---

# 8. Judge Metric 산출

판정 입력은 이 계층에서 칸 단위로 누적된다.

- 유효타, 블록된 타격, 회피시킨 공격, 다운
- 손상 품질 가중

23번의 2단 집계(턴 → 라운드 → 경기)가 이 값을 받는다.
판정을 위해 별도의 경기 요약을 다시 계산하지 않는다.

---

# 9. 미결 항목

- 다운 이후 재개 처리와 카운트 규칙의 Ruleset 차이
- 동시 다운 시 처리
- `impact_variance` 0.07의 타당성. 체감 가능하되 인과를 가리지 않는 폭
- 상태 임계값 실측 밸런싱

---

# 10. 검증 기준

- 같은 Seed·계획·설정에서 결과와 이벤트 순서가 완전히 동일하다
- 난수를 제거해도 승패가 대체로 유지된다. 난수가 승자를 바꾸지 않는다
- 같은 칸의 상호 타격이 함께 반영되며 동시 KO가 성립한다
- 스태미너 부족이 해당 동작만 실패시키고 자원이 음수가 되지 않는다
- 궤도가 맞지 않는 회피는 반드시 피격되고 카운터를 얻지 못한다
- 블록의 스태미너 수지가 공격자보다 유리하다
- 같은 공격이 경기 초반과 후반에 다른 상태 전이를 만든다
- Read Confidence가 최대여도 방어가 100%가 되지 않는다
- 모든 결과 이벤트에 `cause_tags`가 비어 있지 않다
