# 검증·보정 환경 지침

> 대상: 이 저장소에서 밸런스·전투 코드·콘텐츠를 건드리는 사람
> 설계 근거는 [34번 문서](../design/34_ai_equilibrium.md)에 있다. 이 문서는 **운영 방법**이다.

---

# 1. 네 가지 도구

| 도구 | 답하는 질문 | 소요 |
|---|---|---|
| `npm test` | 규칙이 깨졌는가 | 수 초 |
| `npm run balance` | 전략 다양성과 세계가 건강한가 | 수십 초 |
| `npm run calibrate` | 최적 플레이는 무엇이고 AI는 얼마나 강한가 | 2~3분 |
| `node tools/calibrate.mjs policies` | **조건부 카드가 실제로 쓰이는가** | 5~15분 |

넷은 서로를 대체하지 않는다.
테스트는 **불변식**을, balance는 **분포**를, calibrate는 **최적해**를 본다.

`calibrate`와 `policies`는 같은 솔버로 **다른 질문**을 푼다.
`calibrate`는 "한 경기 내내 반복할 최선의 콤보"를, `policies`는 "매 턴 다시 결정하는 최선의 규칙"을 찾는다.
이동·회피·각처럼 **읽고 나서 쓰는 카드**는 앞의 질문으로는 절대 가치를 보일 수 없다.

# 2. 무엇을 바꿨을 때 무엇을 돌리나

## 카드 수치를 바꿨다 (`config/combat_prototype.json`의 `cards`)

```bash
npm test                       # 불변식 확인
npm run balance                # 분포 확인
npm run calibrate:check        # 반드시 실패한다
npm run calibrate              # 재계산
npm test                       # 보정된 AI 기준으로 다시 확인
```

`calibrate:check`가 실패하는 것이 **정상**이다. 카드가 바뀌면 이전 균형은 다른 게임의 정답이다.

## 전투 판정 코드를 바꿨다 (`dist/engine.js`)

위와 동일하다. 지문은 Config뿐 아니라 **엔진 소스도 해싱**하므로 코드 변경도 잡아낸다.

이 규칙은 실제 사고에서 나왔다. 처음에는 Config만 해싱했는데 RNG 수정이 계획의 가치를 바꿨음에도
지문이 그대로여서 낡은 AI가 그대로 남았다. **판정 코드도 규칙이다.**

## 조건부 카드를 추가/삭제했다 (이동·회피·각·반응형)

```bash
npm test
node tools/calibrate.mjs policies
```

새 카드를 `dist/policy.js`의 **역할 목록에 반드시 넣는다.** 어느 역할에도 없으면
어떤 정책도 그 카드를 던질 수 없어 사용률 0으로 나온다. 테스트가 이를 잡아 준다.
`policies` 출력의 "어떤 역할에도 없어 애초에 나올 수 없는 카드" 줄을 먼저 확인한다.

## 카드를 추가/삭제했다

```bash
npm test                       # 삭제된 카드를 참조하는 곳을 잡는다
npm run calibrate              # 새 카드가 균형에 들어가는지 본다
npm run calibrate:report       # "균형에서 쓰이지 않는 카드" 확인
```

새 카드가 `report`의 미사용 목록에 계속 나오면 **죽은 콘텐츠**다. 수치를 고치거나 빼야 한다.

## 세계·성장·경제를 바꿨다

```bash
npm test
npm run balance                # world / campaign / growth 지표
```

전투가 안 바뀌었으면 재보정은 필요 없다.

# 3. 숫자 읽는 법

## `calibrate`

| 값 | 의미 | 위험 신호 |
|---|---|---|
| **게임 값** | 대칭 제로섬의 균형값 | **0이 아니면 버그다.** 전투에 좌우 비대칭이 생겼다는 뜻 |
| **외부 최적대응 이득** | 풀 밖에서 찾은 계획이 균형을 이기는 정도 | 1에 가까우면 미수렴. 라운드나 풀을 키운다 |
| 풀내 exploitability | 이미 아는 계획만 본 값 | **수렴 판단에 쓰지 말 것.** 항상 낙관적이다 |
| 지지집합 크기 | 균형이 섞는 계획 수 | 3 근처에서 멈추면 미수렴 신호 |

**수렴 전(외부 이득 0.2 초과) 해에서는 미사용 카드 목록을 읽지 말 것.**
탐색이 그 카드를 잘 쓰는 계획에 닿지 못했을 뿐일 수 있다. `report`가 이 경우 경고한다.
카드를 추가하면 계획 공간이 커지므로 이전과 같은 풀·라운드로는 수렴하지 않는다.

**풀 내부 값과 외부 값을 혼동하는 것이 가장 흔한 함정이다.**
실제로 풀 내부 0.012인데 외부 이득이 1.0인 상태가 있었다. 완전히 착취 가능한데 안전해 보였다.

## `calibrate policies`

| 값 | 의미 | 위험 신호 |
|---|---|---|
| 게임 값 | `calibrate`와 같음 | 0이 아니면 버그 |
| **카드 사용률** | 균형 혼합을 재생시켜 타임라인에 오른 카드 비율 | 0%인 카드가 진짜 죽은 후보 |
| 어떤 역할에도 없는 카드 | 정책이 애초에 던질 수 없는 카드 | **하나라도 있으면 사용률 표 전체가 무의미하다** |
| 외부 최적대응 이득 | `calibrate`와 같은 뜻 | 0.2 초과면 사용률 표를 근거로 수치를 바꾸지 않는다 |

사용률은 **정책의 규칙이 아니라 실제 타임라인에서** 센다.
정책이 규칙에 `power`를 적어 두어도 그 규칙이 한 번도 발동하지 않았다면 헤비는 나오지 않은 것이다.

정책 쪽은 시드 3개로 잰다. 시드 하나면 페이오프가 승·패·무뿐이라 행렬이 ±1 토너먼트가 되고
fictitious play가 순환 사이를 진동한다. **그래서 `calibrate`의 이득값과 직접 비교하지 않는다.**

## `balance combat`

**한 매치업 안의 승률은 0%나 100%로 나온다.** 고정 계획 + 결정론적 판정이라 당연하다.
의미 있는 신호는 **이긴 프로필 수**다.

| 분포 | 판단 |
|---|---|
| 3승이 있음 | 지배 전략. 가장 나쁜 신호 |
| 0승이 많음 | 죽은 전략이 많음 |
| 1~2승에 몰림 | 건강함 |

## `balance combat N equilibrium`

보정된 AI를 상대로 잰다. **고정 패턴 상대 측정은 과대평가한다.**

실측: 고정 패턴 상대로 3/3 지배하던 계획 두 개가 균형 AI 상대로는 16%였다.
지배적으로 보이던 것이 사실은 **손으로 쓴 패턴의 허점**이었다.

새 카드가 세 보인다면 균형 AI 상대로 다시 재보고 판단한다.

# 4. 깨면 안 되는 불변식

테스트가 강제한다. 실패하면 수치가 아니라 **구조가 잘못된 것**이다.

| 불변식 | 이유 |
|---|---|
| 난이도가 전투 판정을 바꾸지 않는다 | 바꾸면 결과를 매치업으로 설명할 수 없다 |
| 난수는 위력 편차에만 들어간다 | 명중·블록·회피·피니시·승자 Roll은 Config 금지 목록 |
| 페이오프 행렬이 반대칭이다 | 깨지면 좌우 비대칭 버그 |
| 기준 난이도 등급이 중립이다 | 아니면 측정한 밸런스가 어떤 등급도 설명 못 한다 |
| 긴 가드가 짧은 가드보다 성기게 막는다 | 아니면 긴 가드가 구조적으로 지배 전략 |
| 점수는 가한 손상을 따른다 | 포화된 부위를 계속 때리는 것이 최적해가 된다 |
| 계산 가능한 값은 저장하지 않는다 | 밸런스 패치와 세이브가 어긋난다 |
| Evidence 출처 이벤트는 축약하지 않는다 | 과거 자료 재해석이 불가능해진다 |

# 5. 이미 밟은 함정들

같은 실수를 반복하지 않도록 기록한다.

**고정 패턴을 상대로 밸런스를 판단했다.** 패턴은 착취 가능하므로 그 상대의 승률은 실력이 아니라
패턴의 허점을 잰 것이었다. 균형 AI 상대로 재야 한다.

**AI가 약해서 생긴 문제를 카드 수치로 고치려 했다.** 잽이 지배적이길래 비용을 올렸더니 **더 나빠졌다.**
AI 패턴도 잽을 쓰기 때문이다. 지배 전략이 보이면 먼저 "이게 좋은 AI 상대로도 지배적인가"를 묻는다.

**난수 품질을 의심하지 않았다.** xorshift32는 인접 시드의 첫 출력이 강하게 상관된다.
연속 시드가 0.94와 0.47을 번갈아 내서 계획 선택이 사실상 2진값이었고,
**그 위에서 측정한 밸런스는 전부 무효였다.** 시드 기반 선택을 추가하면 분포를 먼저 눈으로 확인한다.

**한 번에 하나씩 최적 대응을 추가했다.** 이 게임은 강하게 순환적이라 수렴하지 않는다.
상위 K개를 함께 넣어야 지지집합이 자란다.

**수렴하지 않은 해에서 죽은 카드를 읽었다.** 카드 3종을 추가하자 미사용이 0에서 7로 뛰었는데,
새 카드뿐 아니라 멀쩡하던 기존 카드까지 목록에 올랐다. 풀을 26에서 40으로 키우니 4종으로 줄었다.
**카드가 늘면 계획 공간이 커져 같은 설정으로는 수렴하지 않는다.**
이 상태에서 수치를 조정했다면 잘못된 지표에 게임을 맞출 뻔했다.

**반응형 카드를 고정 계획 솔버로 재려 했다.** 균형 솔버는 한 경기 내내 같은 계획을
반복한다고 가정하는데, 이동과 사이드 스텝은 상대를 읽고 쓰는 카드다.
"균형에 안 나온다"는 결과는 카드가 약하다는 증거가 아니라 **질문이 틀렸다는 증거**였다.
`calibrate policies`가 그 질문을 고친다. 조건부 카드는 이제 이쪽으로 판단한다.

**정책이 볼 수 있는 것을 정의하면서 "반복했는가"를 자기 자신과 비교했다.** 직전 한 턴만 들고
비교하니 항상 참이었고, 규칙은 늘 발동했다. 과거 **두 턴**이 있어야 반복을 말할 수 있다.

**정책 사용률을 규칙에서 세려 했다.** 발동하지 않은 규칙은 비용도 효과도 없다.
혼합을 실제로 재생시켜 타임라인을 세는 것만이 정직하다.

# 6. 현재 기준선

변경 전후를 비교할 기준값이다. 재측정하면 이 표를 갱신한다.

| 항목 | 값 |
|---|---|
| 테스트 | 290개 |
| Action Card | 17종 (공격 7 / 가드 3 / 회피 3 / 이동 2 / 기타 2) |
| 정보 스킬카드 | 5종 |
| 스타일 스킬카드 | 6종 (축 중복 없음) |
| 상대 프로필 | 3종 |
| 균형 지지집합 | 20개 계획 |
| 외부 최적대응 이득 | 0.422 (**수렴 전**) |
| 균형 미사용 카드 | 미판정 (수렴 전이라 읽을 수 없음) |
| 정책 균형 (풀 118, 14라운드, 7분) | 지지집합 18개, 게임 값 0 |
| 정책 균형 — 외부 이득 | 0.317 (**수렴 전**) |
| 정책 균형 — 타임라인 미등장 카드 | `lowguard` 1종 (수렴 전이라 확정 아님) |
| Config 로드+검증 | 31ms |
| 교환 판정 | 0.46ms |
| 월드 10년 생존 | 66/104, 챔피언 재임 2.0년 |
| 캠페인 완주율 | 약 12% (24시드 중 3) |
| 캠페인 Part 2 도달 | 24시드 중 7 |

**14종 전부 균형에 등장한다.** 죽은 콘텐츠가 없는 상태이며, 이것이 유지 기준이다.

거기까지 가는 데 세 종류의 원인이 있었고 진단이 서로 달랐다.

`hook`·`flicker`는 **값이 틀렸다.** `hook`은 `cross`보다 비싸면서 `advance`에 역할을 뺏혔고,
`flicker`는 리치를 빼면 `jab`의 하위호환이었다. 비용으로 해결됐다.

`lowguard`는 **막을 이유가 없었다.** 몸통은 KO가 나지 않으니 지킬 가치 자체가 없었다.
바디 피니시를 도입해 고쳤는데, 충격 임계만으로 하면 전부 아니면 전무가 된다(임계 10에서 28/30, 11에서 0/30).
**상대가 지쳐 있을 것**을 함께 요구해 누적형으로 바꿨다. 그 뒤에도 안 쓰였는데, 남은 원인은 값이 아니라
**약속의 크기**였다 — 칸당 1.00으로 가장 싼 카드였지만 8칸 중 3칸을 묶었다. 2칸으로 줄이니 들어왔다.

`sway`는 **가격 대비 커버리지가 좁았다.** 칸당 5.00으로 `guard`(2.00)의 2.5배인데 직선만 피했다.
카운터 창이 그 격차를 감당하지 못했다. 3으로 낮추니 "좁지만 상승 여지" 대 "넓지만 새는" 교환이 성립했다.

**셋 다 진단이 달랐다는 점이 요점이다.** 죽은 카드를 보면 값부터 만지지 말고
왜 안 쓰이는지 먼저 물어야 한다.

## 알려진 문제: 커리어 사다리가 가파르다

캠페인 하네스가 양측 모두 균형에서 계획을 뽑도록 바뀌면서(이전에는 주인공만 고정 계획),
완주율이 75%에서 12%로 떨어졌다. **이전 수치는 주인공만 유능하고 상대는 손으로 쓴 패턴이던 조건의 값**이었다.

병목은 클럽 챔피언이 아니다. 챔피언 레벨을 82에서 72로 낮춰도 완주는 3/24에서 4/24로만 움직인다.
**Part 2 도달 자체가 24시드 중 7**이고, 주인공은 커리어 내내 punch 62 → 73으로만 자란다.
승률이 5할 근처라 승격에 필요한 연승이 잘 나오지 않는다.

성장 곡선과 클럽 승격 조건을 함께 봐야 하는 문제이며 전투 밸런스가 아니다. 다음 패스의 과제다.

# 7. 새 시스템을 붙일 때

1. **Config에 수치를 둔다.** 코드에 숫자를 박지 않는다
2. **검증기를 함께 쓴다.** 설계 문서의 "검증 기준"을 로더가 실행하게 한다
3. **불변식을 테스트로 고정한다.** 특정 수치가 아니라 성질을 고정한다
4. 전투에 영향이 있으면 **재보정한다**
5. 지침서의 기준선 표를 갱신한다

수치를 고정하는 테스트는 튜닝할 때마다 깨진다. 성질을 고정하는 테스트는 튜닝을 견딘다.
`tests/balance-invariants.test.mjs`가 후자의 예다.
