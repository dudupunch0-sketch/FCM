# 1. 어디서 이어받나

```
브랜치   claude/work-tree-design-spec-3f7008
원격     https://github.com/dudupunch0-sketch/FCM.git
```

`main`은 9월 10일 시점에 멈춰 있다. **9월 12~13일 작업은 전부 이 브랜치에 있다.**

```bash
git clone https://github.com/dudupunch0-sketch/FCM.git
cd FCM
git checkout claude/work-tree-design-spec-3f7008
npm test
```

설치할 것이 없다. **의존성 0개**이고 `node_modules`도 없다. Node 18 이상만 있으면 된다.
`npm test`가 `pretest`로 `dist/config/`를 자동 생성하므로 별도 준비가 필요 없다.

# 2. 환경 제약 — 모바일·클라우드에서 무엇이 되고 무엇이 안 되나

| 명령 | 소요 | 클라우드 |
|---|---|---|
| `npm test` | 21초 | 문제없음 |
| `npm run calibrate:check` | **0.2초** | 문제없음 |
| `node tools/calibrate.mjs grammar` | 수 초 | 문제없음 |
| `npm run calibrate` (solve) | 2~3분 | 대개 가능 |
| `node tools/calibrate.mjs matchup` | 10~15분 | **실행 시간 제한 주의** |
| `npm run calibrate:policies` | 13~50분 | **아마 불가** |

전부 순수 계산이다. 네트워크도 쓰지 않고, 파일은 `config/`를 읽고 JSON 두 개를 쓴다.
**막히는 것은 환경이 아니라 벽시계 시간뿐이다.**

시드 기반 난수라 **다른 기계에서도 같은 시드면 같은 결과**가 나온다. 클라우드에서 돌린 값을
로컬 값과 그대로 비교해도 된다.

## 오래 걸리는 계산을 피하는 법

1. **규칙을 안 바꾸는 작업**(문서·UI·테스트)은 `check`만 돌리면 된다. 0.2초다
2. 규칙을 바꿨다면 `solve`만 먼저 돌린다. `policies`는 조건부 카드를 판단할 때만 필요하다
3. 매치업 측정은 라운드·풀을 줄여 방향만 본다. **수렴 전 값은 확정값이 아니라는 표시가 출력에 나온다**

## 카드 이름은 이제 재계산을 부르지 않는다

지문에서 `name`·`short`·`description`·`note*`를 제외했다. 표시 문구를 다듬는 것은
규칙 변경이 아니므로 저장된 AI가 낡지 않는다. 수치·종류·궤도·손을 바꾸면 여전히 재계산이 필요하다.

# 3. UI를 직접 보려면

```bash
npm start        # http://localhost:8000
```

의존성 없는 Node 정적 서버(`tools/serve.mjs`)를 쓴다. 예전에는 `python3 -m http.server`였다.

브라우저 확인이 안 되는 환경이라면 **이것을 기억해 둘 것**: 9월 13일에 `backstep`·`stepin`·`switch`
세 장이 UI에서 아예 선택 불가였던 것을 브라우저로 보고서야 발견했다. 엔진에도 있고 솔버도 쓰는데
덱 분류 필터가 종류를 하나하나 열거하고 있어서 새 종류가 조용히 사라졌다.

지금은 분류를 **배제 방식**으로 바꾸고 "모든 카드가 정확히 한 분류에 있다"를 테스트가 강제한다.
그래도 화면 붕괴·겹침 같은 것은 테스트가 못 잡는다.

## 우선순위

## 1순위 · 도구 신뢰도

**외부 최적대응 이득이 노이즈가 큰 하한 추정치다.** 무작위 계획 400개를 뽑아 최댓값을 취하므로
뽑기에 따라 흔들린다. 같은 설정인데 풀 40에서 0.060, 풀 56에서 **0.229**가 나온 적이 있다.

수렴 판정을 이 값 하나로 하고 있는데, 그러면 안 된다. 고치는 방향:

- 시드를 바꿔 여러 번 재고 최댓값을 취한다
- 무작위 표본에만 의존하지 말고 이웃 탐색을 섞는다

계산이 가벼운 쪽 작업이라 모바일에서도 할 만하다.

## 2순위 · 전투

| | |
|---|---|
| `mixed` 3/3 지배 | `['sway','body','cross','rest']`. 단일 카드 스팸이 아니라 덜 나쁘다 |
| 오픈 가드 미수렴 | 0.376. 공유 풀이 **서로 다른 두 문제**를 덮어야 해 예산이 두 배 필요하다 |
| `weave` 미등장 | `slip` 역할이 안 팔린다 |
| 오픈 가드 교환 비대칭 | 훅 위력만 바뀐다. 바깥발 위치 싸움 같은 축이 없다 |
| 스위치 직후 취약점 | 칸과 비용만 쓰고 별도 노출이 없다 |

## 3순위 · 커리어

완주율 33%, **평균 패배 23.7회**. 승률이 5할 근처라 승격에 필요한 연승이 나오지 않는다.
성장 곡선과 승격 조건을 함께 봐야 하는 문제이며 전투 밸런스가 아니다.

## 보류 · 그래플링

`config/grappling.json`과 검증기는 있지만 **엔진 연결이 0줄**이다. 27번 명세만 존재한다.
사실상 두 번째 전투 시스템이고, 복싱 축도 아직 다 여물지 않았다. 먼저 열 이유가 없다.

# 5. 반드시 지킬 것

지침 문서([`docs/guide/testing_and_calibration.md`](../docs/guide/testing_and_calibration.md))에
자세히 있지만, 이어받는 사람이 가장 먼저 어길 만한 것들만 옮긴다.

- **수렴 전 해의 미사용 카드 목록을 읽고 수치를 조정하지 말 것.** 도구가 경고를 띄운다
- **모든 카드를 균형 사용률로 재지 말 것.** 하이리스크 카드는 드물게 나오는 것이 정상이고,
  재야 할 것은 **읽기가 맞았을 때의 전환율**이다
- **고친 것이 균형을 전혀 안 바꿔도 정상일 수 있다.** 조건부 효과는 그 조건이 걸리는 상황을
  따로 재야 한다. 집계 지표로 검증하면 언제나 "효과 없음"이 나온다
- **오픈 가드는 대칭 게임이 아니다.** 페이오프 행렬을 반대칭으로 강제하면 없는 결과를 지어낸다
- 규칙이 바뀌면 `calibrate:check`가 실패한다. **낡은 AI를 그대로 두지 말 것**
